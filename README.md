# PDF Splitter

複数の PDF をつなげたうえで、指定したサイズ（MB）より小さいファイルに分割する Web アプリです。Flask と [qpdf](https://qpdf.readthedocs.io/) で動作します。

メールの添付やアップロードにサイズ制限があるときに、大きな PDF を制限内のファイルに分けるといった用途を想定しています。

**デモ:** https://pdf-splitter-hm06.onrender.com

## 特徴

- 複数の PDF を、並べた順につなげて分割
- 各出力ファイルが指定サイズを超えないよう、実際に書き出したサイズを測りながらページの区切りを決める
- ページの抽出と結合は qpdf で行い、ページを画像に変換したり描き直したりしない
- 大きなファイルは 50MB ずつに分けてアップロードするため、1 回のリクエストが大きくなりすぎない
- 処理の進み具合とログをブラウザに表示
- 出力ファイルを 1 つずつ、または ZIP でまとめてダウンロード

## 必要なもの

- Python 3.10 以上
- qpdf

qpdf は次のコマンドでインストールできます。

```bash
# macOS
brew install qpdf

# Debian / Ubuntu
sudo apt install qpdf

# Windows（Chocolatey）
choco install qpdf
```

## インストールと起動

```bash
git clone https://github.com/mimish0778/pdf-splitter.git
cd pdf-splitter
pip install -r requirements.txt
python app.py
```

ブラウザで http://localhost:5000 を開きます。

ブラウザ側で `crypto.randomUUID()` を使っているため、`localhost` 以外から HTTP で開くと動作しません。ほかの端末から使う場合は HTTPS で配信してください。

### 環境変数

| 変数 | 内容 | 初期値 |
| --- | --- | --- |
| `PORT` | 待ち受けるポート番号（`python app.py` で起動した場合） | `5000` |
| `WORK_ROOT` | アップロードしたファイルと出力ファイルを置く作業ディレクトリの親 | OS の一時ディレクトリ |
| `SECRET_KEY` | Flask のシークレットキー | 起動ごとにランダム |

## 使い方

1. PDF をドラッグ＆ドロップするか、クリックして選びます。複数選べます。一覧の行をドラッグすると順番を入れ替えられます。
2. 「分割上限サイズ」（MB、初期値 200）と「ファイル名プレフィックス」（初期値 `split`）を設定します。
3. 「分割を実行する」を押します。アップロードと分割の進み具合が表示されます。
4. 完了したら、出力ファイルを 1 つずつダウンロードするか、「すべてZIPでダウンロード」でまとめてダウンロードします。

出力ファイルの名前は `{プレフィックス}_001.pdf`、`{プレフィックス}_002.pdf` のように連番になります。ZIP の名前は `split_pdfs.zip` です。

## 分割の仕組み

ファイルを並べた順に 1 つずつ処理します。すべてを 1 つの PDF に結合してから分割するのではないため、作業用のディスクとメモリを抑えられます。

1. 処理中のファイルの残りのページをまとめて書き出し、上限より小さければ、それで 1 つの出力にします。
2. 上限を超える場合は、二分探索で「上限より小さく収まる最大のページ数」を探します。候補ごとに実際に qpdf でページを抜き出してサイズを測ります。
3. 決まった範囲を書き出し、念のためもう一度サイズを確認します。上限以上なら、収まるまで 1 ページずつ減らします。
4. ファイルの最後の部分が上限に満たない場合は、次のファイルの先頭とつなげてから続きを処理します。そのため、1 つの出力ファイルに複数の元ファイルのページが入ることがあります。

ページの抽出と結合には次の qpdf のコマンドを使っています。

```bash
# ページの抽出
qpdf input.pdf --pages . 1-10 -- output.pdf

# 結合
qpdf --empty --pages a.pdf 1-5 b.pdf 1-20 -- output.pdf
```

出力ファイルはすべて指定したサイズより小さくなります。ただし、1 ページだけで上限を超えるページがある場合は、そのページを単独のファイルとして出力します。この場合は上限を超えたファイルになり、ログに警告が表示されます。

## API

ブラウザの画面は次の API を使っています。

| メソッド | パス | 内容 |
| --- | --- | --- |
| `POST` | `/api/upload_chunk` | ファイルの一部（チャンク）を受け取る。フォームの項目は `session_id`、`chunk_index`、`total_chunks`、`filename`、`data` |
| `POST` | `/api/finalize` | アップロード済みのファイルの分割を開始する。項目は `session_id`、`size_mb`、`prefix`、`file_order`（処理順のファイル名の JSON 配列） |
| `GET` | `/api/status/<job_id>` | 状態（`running` / `done` / `error`）、進み具合、ログ、出力ファイル名の一覧を返す |
| `GET` | `/api/download/<job_id>/<filename>` | 出力ファイルを 1 つダウンロードする |
| `GET` | `/api/download_zip/<job_id>` | すべての出力ファイルを ZIP でダウンロードする |

分割はバックグラウンドのスレッドで実行されます。ジョブ ID には `session_id` がそのまま使われます。

## デプロイ

### Docker

`Dockerfile` は qpdf をインストールし、gunicorn で起動します。待ち受けるポートは環境変数 `PORT` で指定します。

```bash
docker build -t pdf-splitter .
docker run -p 5000:5000 -e PORT=5000 pdf-splitter
```

### gunicorn

```bash
gunicorn app:app --bind 0.0.0.0:5000
```

ジョブの状態はプロセスのメモリに保存しているため、ワーカーは 1 つで起動してください。`-w 2` などで複数のワーカーを起動すると、状態の確認やダウンロードのリクエストがジョブを持っていないワーカーに届き、「ジョブが見つかりません」となることがあります。

`build.sh` は、Docker を使わない環境向けに qpdf と Python のパッケージをインストールするスクリプトです。

## 注意事項

- アップロードしたファイルは分割が終わると削除されます。出力ファイルとジョブの情報は、1 時間たつと次のリクエストの処理時に削除されます。
- ジョブの情報はメモリにしか保存しないため、サーバーを再起動すると、完了したジョブの出力もダウンロードできなくなります。
- 認証の仕組みはありません。公開する場合は、誰でもアップロードできる状態になることに注意してください。
